# Plan: Certificate Verification Platform

Implement the full GDG certificate verification platform by aligning the existing Next.js 16 codebase with the PRD: fix the Prisma schema, complete auth and route handlers, add upload + image generation, then build the public and admin UI plus analytics and security guards.

## Steps
1. Baseline alignment and dependencies: confirm App Router conventions from node_modules/next/dist/docs and add missing runtime deps for canvas, QR, Excel parsing, charts, and hashing.
2. Data model and migrations: update prisma/schema.prisma to match PRD entities (Event, Certificate, VerificationLog), fix typos, relations, and defaults, keep UUID IDs, add revokedAt and bannerUrl, and run Prisma migration flow. Depends on step 1.
3. Auth and route protection: complete Google OAuth config in src/app/api/auth/[...nextauth].ts, add admin allowlist by email, and add middleware-based guards for /admin and /api/admin paths. Depends on step 1.
4. Public verification APIs: implement verification JSON in src/app/api/verify/[certId]/route.ts, add certificate image endpoint under src/app/api with cache headers and revoked handling, and log verify requests into the new table. Depends on step 2.
5. Admin APIs: implement event CRUD and certificate revoke routes under src/app/api matching PRD paths, and either retire or adapt the placeholders in src/app/api/event/[eventId]/route.ts and src/app/api/event/data/upload/route.ts. Depends on step 2.
6. Upload pipeline: build Excel/CSV parsing, Zod validation, duplicate detection, and upsert logic with row-level errors and summary stats; wire it to the admin event detail upload UI. Depends on step 5.
7. Public pages: replace the placeholder landing UI in src/app/page.tsx with the PRD sections and GDG community CTA, and build the verification page under src/app to show valid/invalid states, QR, share, and image embed. Depends on step 4.
8. Admin UI: create admin list, event detail, and certificate detail pages under src/app using shadcn/ui from src/components/ui; add tables, filters, modal create, revoke flow, and CSV export. Depends on step 5.
9. Analytics: implement Prisma aggregate queries for summary cards and chart datasets, and render charts with Recharts in admin pages. Depends on steps 2 and 8.
10. Security and performance hardening: rate limit verify endpoints, validate all inputs with Zod, add cache-control for images, and ensure revoked certs return 404 image + revoked UI. Parallel with steps 7-9 once APIs are stable.
11. QA and polish: verify responsive layouts, accessibility, and key flows; update env var documentation in README or a short setup note. Depends on steps 7-10.

## Verification
1. Run npm run lint and fix lint issues.
2. Run Prisma migration and client generation via npx prisma migrate dev and npx prisma generate.
3. Start npm run dev, then validate: landing, verify page (valid, invalid, revoked), image endpoint caching, admin login, event CRUD, upload, revoke, and analytics charts.
4. Confirm performance targets using simple timing checks and server timing headers on image/verify endpoints.

## Decisions
- Use Google OAuth only for admin auth (no credentials flow in v1).
- Keep UUID-based IDs for certificates and events.
- Implement verification logging in v1 to power the activity chart.
- Stay on current Next.js version in package.json rather than downgrading to 14.

## Further considerations
1. Admin allowlist: single email via env var vs list of allowed emails.
2. Route compatibility: keep legacy /api/event/* endpoints as wrappers or fully migrate to /api/admin/* only.
3. Canvas backend: choose @napi-rs/canvas vs node-canvas based on deployment support and build time.
